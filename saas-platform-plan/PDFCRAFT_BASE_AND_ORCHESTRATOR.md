## 3. Что в PdfCraft есть и чего нет (по README/ROADMAP)

| Нужная нам функция | Состояние |
|---|---|
| Merge, Split, Organize (поворот, удаление, вставка, перемещение) | ✔ есть |
| Защита, формы, комментарии, подписи (частично) | ✔/частично |
| Compress | не упомянуто → добавим сами (есть крейт `optimize`, проверить) ⚠ |
| OCR | Латиница через `ocrs` (rten); **«OCR beyond Latin script» — отсутствует** ✔ |
| Редактирование текста | Частично; CJK/RTL — «thin or missing»; арабский в Add text есть, в Edit text — нет ✔ |
| Перевод | нет → **наше главное дополнение** |
| Office → PDF, PDF → Word | в планах авторов, не готово ✔ |
| Арабский интерфейс | есть каталог ar, но зеркалирование макета не сделано ✔ |
| Устойчивость | fuzzing находит падения и зависания → **серверные задачи только в песочнице** ✔ |

## 4. Как использовать (рекомендация)

1. **Форк-зависимость, а не копия:** подтягивать upstream, свои изменения держать отдельными крейтами/патчами (проще мержить). Пакеты `pdfcraft-*` вызывать из нашего кода как библиотеку.
2. **Слои:**
   - браузер: WASM-сборка PdfCraft для merge/split/organize/images — приватность и нулевая серверная нагрузка;
   - сервер: `pdfcraft-cli` под MCP/командами как «исполнитель» внутри песочницы для тяжёлых и серверных операций;
   - наши модули: перевод, OCR для арабского/латиницы, сжатие, инпейнтинг картинок, биллинг, очередь.
3. **ИИ-управление:** MCP-интерфейс позволяет оркестратору и агентам выполнять операции над PDF одной командой — удобно для автоматизации и тестов.
4. **Конкурентный риск:** базой может воспользоваться любой, поэтому отличие должно лежать не в самой базе, а в **переводе, RTL, нише технических документов, SEO и доверии**. Если на ту же базу посадят десятки сайтов, одинаковые «обёртки» хуже ранжируются — нужен собственный контент.
5. **Зависимость от чужого проекта:** альфа, высокая скорость изменений, возможный разворот планов. Фиксируем версию (commit pin), ведём собственный регресс-набор PDF, держим возможность заменить компонент (pypdf/pikepdf/PDFium из прежнего плана остаются запасным вариантом).
6. **Перед использованием (чек-лист):** `cargo deny check` и `cargo about` на нашем форке; перечитать LICENSE/NOTICE и `docs/brand/LICENSE-brand.txt`; проверить лицензии vendored-крейтов и OCR-моделей, которые скачивает `cargo xtask models` ⚠ (модели в ATTRIBUTION мной не просмотрены); запустить сборку WASM и 100 тестовых PDF.
7. **Остальные Craft-приложения** (PhotoCraft, GridCraft, WordCraft…): теоретически дают будущие продукты (изображения, таблицы), но все альфа. В план 12 месяцев **не включаем**, возвращаемся после MVP.

## 5. Оркестратор: 2 ПК сейчас, любое число потом

### Принципы
- **Pull-модель:** воркеры сами подключаются к координатору по исходящему TLS (ПК не открываются в интернет; домашний IP не светится).
- **Координатор** живёт на дешёвом VPS (≈ $6–10/мес ❓, входит в ваш бюджет $10–40): постоянная доступность, API, БД, очередь, выдача подписанных ссылок. Если VPS не хотите — координатор можно держать на одном из ПК через туннель, но надёжность ниже.
- **Воркер** — маленькая программа-агент на каждом ПК: регистрируется токеном, объявляет возможности, берёт задачи, шлёт heartbeat, возвращает результат.

### Как это работает

| Элемент | Решение |
|---|---|
| Очередь | PostgreSQL (`SELECT … FOR UPDATE SKIP LOCKED`) — без доп. сервисов; позже можно NATS JetStream/Celery, если вырастем ❓ |
| Возможности воркера | Теги: `cpu`, `gpu:6gb`, `ocr`, `translate:ar`, `libreoffice`, `pdfcraft`; планировщик сопоставляет требования задачи и теги |
| Надёжность | Аренда задачи (lease) с таймаутом; нет heartbeat → задача возвращается в очередь; повторы с лимитом; идемпотентность |
| Добавление компьютера | Скопировать агента, выдать токен в админке, запустить — воркер появляется в панели |
| Распределение | По тегам и загрузке: перевод — на GPU-ПК, OCR/PDF — на любой; «дорогие» задачи — по приоритету и кредитам |
| Безопасность | Токен на воркер (отзываемый), mTLS по желанию, задачи содержат только ID и подписанные URL, файлы шифруются, TTL ≤ 1 ч, песочница на воркере (контейнер без сети, лимиты) |
| Файлы | Вход/выход через VPS-хранилище с подписанными ссылками; воркер не хранит файлы после задачи |
| Отказоустойчивость | Выключен GPU-воркер → задачи перевода ждут/показывается «очередь»; CPU-задачи берёт другой воркер; клиентские инструменты вообще не зависят от кластера |
| Мониторинг | Панель: воркеры, очередь, время задач, ошибки, температура/VRAM; алерты |
| Планы на 6 ГБ GPU | Одна LLM-задача на карту; несколько карт на одном ПК = несколько воркеров с `CUDA_VISIBLE_DEVICES` |

### Оркестрация ИИ-агентов
Для автоматизации (SEO/контент/тесты) отдельно существует «плановый слой» — скрипты по расписанию; воркеры PdfCraft и MCP — «исполнительный слой». Агенты Claude не крутятся в фоне постоянно: они участвуют в разработке и еженедельном анализе (см. CLAUDE_AUTONOMY_AUDIT).

## 6. Влияние на дорожную карту и стоимость

- Разработка MVP клиентских инструментов сокращается (готовые merge/split/organize), но нужны: сборка WASM, интеграция в Next.js, регресс-набор, ребрендинг, сжатие.
- Расходы без изменений: $10–40/мес (VPS + домен + электричество); платежи — позже.
- Новый риск: качество и стабильность альфы. Контрольная точка: после 2 недель сборки решаем «PdfCraft как основа» или «запасной стек» (pdf-lib/pypdf/qpdf).
